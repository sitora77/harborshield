# 真实数据实验：先学会预测港口活动，不冒充预测货物延误

## 这次真正跑了什么？

用 IMF PortWatch 的新加坡港 `port1201` 数据，读取 2022–2024 年
**1,096 条逐日集装箱船靠港记录**，预测“明天会有多少次集装箱船靠港”。
这是基于 AIS 的港口活动观测，不是随机生成的船舶记录，也不是公司订单。
UTC 日期和靠港次数保留来源的原值。它不代表 TEU、独立船舶数、等待时间
或单票货物延误。新加坡周边有其他港区，本实验没有把它们混成一个总数。

## 为什么不用整个数据一起训练？

把未来数据交给模型，再说它“预测准确”，没有说服力。所以按时间分成：

| 时间 | 作用 | 天数 |
|---|---|---:|
| 2022 | 拟合岭回归；其他方法只读取此前记录 | 365 |
| 2023 | 对比五种方法，用 MAE 选定一个 | 365 |
| 2024 | 最终测试，不能拿来选方法 | 366 |

预测 2024 年 6 月 2 日时，可以用此前已观察到的 6 月 1 日记录，不能用
6 月 2 日实际值。岭回归系数在进入 2024 年前冻结，不在测试年重新拟合。
这是**逐日向前的一天期预测**，不是年初一次预测整年。

另一个局限：数据是后来下载的历史版本，可能已经修订。不能把回测说成
“模型在 2024 年当时已经取得这些效果”，也没有证明实时发布延迟足够短。

## 五种方法其实很容易理解

1. 昨天多少次，明天就预测多少次。
2. 上周同一天多少次，明天就预测多少次。
3. 用之前 28 天的平均次数。
4. 用此前四周同一星期几的平均次数。
5. 岭回归：参考此前第 1、2、7、14、28 天的次数和星期几，用固定惩罚
   控制系数。它是可解释的小模型，不是神经网络或大模型。

2023 年选中了“此前 28 天均值”。进入 2024 年后，它的平均绝对误差
约 **3.29 次/天**，昨天基线约 **4.80 次/天**，误差减少约 **31.4%**。
这不是“准确率 96.7%”，也不是减少了 31.4% 的货损或成本。
岭回归在最终测试中没有胜过这个简单均值，应如实报告。

- MAE：把每一天“预测减实际”的绝对值取平均；越小越好。
- RMSE：对较大偏差更敏感；单位仍是次/天。
- WAPE：所有天的绝对误差总和，除以真实次数总和；不是分类准确率。
- 图表为了容易阅读显示周均值；评估依然用每一天，不用平滑后的图算误差。

## 如何在你的电脑复现

在 HarborShield 文件夹中，先使用已有项目环境。无需申请 API 密钥，
无需下载新数据即可复现仓库里固定的快照：

```bash
python scripts/run_real_data.py
python -m unittest discover -s tests -v
streamlit run app.py
```

打开本地应用的 **Real-data backtest** 标签。输出包含方法比较、2024 年
每日对照、每月诊断和完整结果下载。改变构造订单金额不会改变真实数据结果。

需要有意刷新来源时才运行：

```bash
python scripts/fetch_portwatch.py
# 连接会截断时，可选择同一接口的 curl 传输方式：
python scripts/fetch_portwatch.py --transport curl
python scripts/run_real_data.py
```

数据更新可能改变结果，所以来源快照、校验值和报告应一起更新。缺失日期、
重复、空值、负数或来源校验不一致会阻止实验，不会替换成模拟记录。

## 与 SCM、ISE、MTM、智慧交通、金融方向的关系

这个模块对应货代运营中的“港口活动监测”任务：先建立简单预测基线，
再观察预测误差异常的日期，决定是否需要进一步核查船期和交付风险。
它展示真实数据获取、质量检查、时间序列验证和模型比较。

不能直接说“船多了，所以订单一定延误 2.5 天”。若要连接到 SCM 补货模型，
还需要同港口、同日期的实际等待时间、计划/实际交付和库存需求；若要证明
金融效果，还需真实付款、运价或融资成本观测。当前保险、订单和现金流
模块仍是明确标注的构造分析。项目没有真实企业上线或收益证明。

这些练习用于学习，不要拿最终测试年反复调参后仍宣称它是未见过的测试集。

1. 找到 2024 年误差最大的一天，手算它的 28 日平均预测和绝对误差。
   只能说“这天难预测”；没有其他数据时，不要编造事故或拥堵原因。
2. 比较一个月份的逐日误差与图中的周平均，解释为什么平滑曲线更好看，
   却不能代替逐日评估。
